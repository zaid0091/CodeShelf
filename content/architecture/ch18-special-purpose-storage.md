# Chapter 18: Special Purpose Storage

> **Explore specialized data stores. Compare document, wide-column, graph, time-series, and vector database use cases.**

---

## Specialized Databases

As systems grow, a general-purpose SQL or NoSQL database may fail to meet performance requirements for specialized tasks. Modern architecture utilizes different databases for different workloads (Polyglot Persistence).

---

## Special Purpose Database Categories

### 1. Key-Value Stores (e.g., Redis, Memcached)
Data is stored as simple key-value pairs in memory.
*   *Use Case:* Session caching, user carts, rate limiting, and pub/sub message brokers.

### 2. Document Databases (e.g., MongoDB, CouchDB)
Data is stored as self-describing documents (JSON/BSON format).
*   *Use Case:* Content management, e-commerce product catalogs, and user profiles.

### 3. Wide-Column Stores (e.g., Cassandra, ScyllaDB)
Rows can contain dynamic columns. Designed to handle petabytes of data across distributed clusters with masterless architectures.
*   *Use Case:* Event logging, IoT sensor feeds, and telemetry analytics.

### 4. Graph Databases (e.g., Neo4j, Amazon Neptune)
Data is represented as **Nodes** (entities) and **Edges** (relationships), allowing fast traversal of complex networks.
*   *Use Case:* Social networks, recommendation engines, and fraud detection.

### 5. Time-Series Databases (e.g., InfluxDB, TimescaleDB)
Optimized for storing timestamped data sequences that are append-only.
*   *Use Case:* Server CPU/memory monitoring metrics, stock market histories.

### 6. Vector Databases (e.g., Pinecone, Milvus, pgvector)
Stores multi-dimensional vector embeddings generated by machine learning models, allowing fast similarity searches.
*   *Use Case:* Recommendation algorithms, LLM semantic search, and image similarity matching.

---

## Best Practices & Pitfalls

| Best Practice | Common Pitfall |
|---------------|----------------|
| Select specialized databases based on mathematical access properties (e.g., use Graph DBs if query paths traverse more than 3 relationship hops). | Using a relational SQL database with recursive table joins to represent a complex social network friend graph. |

---

## Interview Points

> **📌 Interview Point 1: Why are Graph databases faster than SQL for highly connected datasets?**
> SQL databases must run expensive JOIN operations at runtime, scanning table indexes to link rows. Graph databases use "index-free adjacency"—each node contains direct memory pointers to its connected neighbors, turning relationship traversals into simple pointer lookups.

## Exercises

### Exercise 1: Select the database ⭐
**Task:** Select the database type for a system that records temperature readings from 10,000 IoT sensors every 5 seconds.

<details>
<summary>✅ Solution (click to reveal)</summary>
**Time-Series Database** (like InfluxDB or TimescaleDB). It is optimized for high-volume append-only writes of timestamped data and offers built-in aggregation queries (e.g., average hourly temperature).
